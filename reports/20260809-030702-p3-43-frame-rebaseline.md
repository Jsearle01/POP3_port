### 3 — Reasoning

#### 3A — Method: the VBL spin clock, and ablation for the split

MAME 0.281's Lua wrapper exposes **no cycle counter** and `machine.time` is quantised to the scheduler
timeslice (idioms §0), so cost is measured off the VBL spin-wait — `hal_vbl_spin` is
`cmpb <hal_frame_lo` (4) + `beq` taken (3) = **7 cy/iteration**, burning every cycle the engine is not
working:

```
work = frames_elapsed × 29,859 − spins × 7
```

Intra-iteration cycles cannot be read at a boundary, so the split is by **difference**: run the same build
with one component removed and subtract. **Every mode ablates at run time** — patching the call site or
forcing a branch from Lua — so no `src/` file is touched and all five modes measure the identical binary.

| mode | how | iters | frames/iter | work cy | `chars_frame` | `flicker` |
|---|---|---|---|---|---|---|
| `full` | — | 694 | 2.161 | 57,074 | 1.00 | 1.00 |
| `nopeel` | `ch_anymove` reads forced to 0 | 750 | 2.000 | 31,672 | 1.00 | 1.00 |
| `nochars` | `jsr [CHARS_TAB]` → NOP | 1501 | 1.000 | 2,871 | **0.00** | 1.00 |
| `noflicker` | `jsr flicker` → NOP | 750 | 2.000 | 54,829 | 1.00 | **0.00** |
| `neither` | both | 1501 | 1.000 | 343 | **0.00** | **0.00** |

#### 3B — What the numbers say

**The character path costs 54,203 cy — 183% of the frame budget on its own.** That is the subsystem the whole
P3.33-P3.42 arc has been optimising the *representation* of, and it is already 1.8 frames of work before any
run-time shift is contemplated.

**The peel is 25,402 cy — 86% of a budget, 44.5% of the frame.** Erase + save, both characters, every frame.
P3.42 measured that the frame-wide peel-skip **never fires** in this scene (0 of 694 iterations), so this cost
is paid unconditionally. It is the largest single component and it draws nothing.

**`flicker` is 2,245 cy — 3.9%.** The torches and stars are not the problem, and it is worth saying because
the model charged "two flames, hourglass and four stars" as a material share of its 19,652.

**Everything else is 343 cy.** The loop, the page flip and the IRQ are free at this scale.

#### 3C — Why the model was so far out, stated as fact and not as blame

P3.19's model charged a counted row loop, mode transitions, skip-run pointer advances and 40 cy of per-call
setup across the cels, flames, hourglass and stars — **19,579 cy**, later restated as 19,652. It is arithmetic
over the source, done carefully, and it was re-derived once (P3.37) by *more arithmetic* when a restructure
made it suspect.

**It was flagged as inherited twice** — P3.37 §7 and P3.41 §7 — and both flags were correct and changed
nothing. The figure kept being divided by for six dispatches. **Disclosing a weakness is not testing it**, and
a flag in an uncertainty section makes the weakness look handled.

I am **not** publishing a reconciliation of where the 37,422 cy gap comes from, because I have not measured
that. A rough count of the shipped peel loops lands well below the measured 25,402, in the same direction as
every other counted-vs-executed gap in this project — but that is an observation, not a decomposition, and
turning it into one is §8's follow-up rather than this report's claim.

#### 3D — Two instrument faults, and why the second one removes the obvious fix

**Fault 1 — the address derivation.** `CHARS_TAB` is an `equ`, and lwlink lists `equ` symbols **offset by the
section base**: the map reads `$5040` where the instruction holds `$3040`. The first run therefore looked for
the call site at the wrong address and **ABORTED** instead of patching whatever it found. The byte-verification
guard is the only reason that was a non-event; patching four bytes at an arbitrary address would have produced
a plausible number from a corrupted program. `run_room_test.sh` documents this exact trap for
`GFX_DB_*_BLOCK` — it was written down and I still walked into it, which is the P3.39 pattern in miniature.

**Fault 2 — a read-tap hit is not an execution.** The first ablation gate keyed on the low-level blit counts.
Under `nochars` — character path removed — `blit_cel` still tapped **0.23 hits/iteration**. The counts are real
reads; the inference was wrong twice over:

- **`blit_cel` is shared.** The flame path reaches it too, so a non-zero count cannot say *which* caller is
  alive, and a zero count could not either. **A shared signal cannot attribute.**
- **Read-taps fire on data and dummy reads, not only opcode fetches**, and the PC discriminates:
  ablated run → **`PC=$391B`** (byte read, PC not advanced — not executed); live run → **`PC=$391C`**
  (opcode fetched, PC advanced — executed). Same address, same session, opposite meanings.
- **And the inflation is not uniform**, which kills the obvious fix: in one run `blit_save` tapped at exactly
  `2.00`/iteration (true) while `blit_erase` tapped `4.01` for two real calls. **There is no constant to divide
  out.**

**The fix was to gate on the entry count of the routine actually ablated** — `chars_frame` and `flicker` —
which came out as clean `1.00`/`0.00` and needed no argument at all. Both faults are now
`mame-idioms-coco3-port.md` **§10a**.

**What made this recoverable is that the tool prints UNCONFIRMED instead of a number.** The unconfirmed
difference was 54,203 cy — large, plausible, in the right direction, and *correct as it happens*. Printed
without its gate it would have been believed for the wrong reason.

### 7 — Uncertainty flags

- **This is the CURRENT scene, not `play 13`.** Same subsystems, comparable cel sizes, but not the frame the
  27,482 prediction describes — which, per P3.42 §3C, cannot be run at all until `Vraise`/`Pback` are
  converted. **Do not add 7,830 to 57,074 and call it a verdict**; that would repeat the arc's error in the
  opposite direction.
- **The draw figure (~28,801) is a residual**, not a direct measurement — character path minus peel. It
  inherits both terms' error.
- **The peel is measured but not explained.** 25,402 cy is well above a hand count of the shipped
  `blit_save`/`blit_erase` loops. Either the count is wrong in the familiar direction or something else is in
  that path; §8.2 is the check.
- **Blit-primitive tap counts in §5's table are NOT execution counts** (§3D) — `erase 4.01` is two real calls.
  They are printed because they were the evidence trail; only the `chars`/`flicker` entry columns are sound.
- **The 29,859 cy/frame constant** is inherited (894,886 Hz × 2 ÷ 59.94). The headline result does not depend
  on it; the cycle figures do.
- Carried: the scene's cels are unenumerated; `aboutface` unexercised and invalidating baked parity; only
  phase 1 of the shifter was timed; the ~0.55-frame cadence overrun — now explained, since a 1.91-budget frame
  cannot hold a 2.60-frame cadence.

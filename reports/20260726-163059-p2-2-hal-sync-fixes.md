### 3 — Reasoning

#### 3.1 — Phase 0: the push path (verified before anything else)
Karateka's remote is **SSH** (`git@github.com:Jsearle01/karateka-coco3.git`), not the credential-embedded HTTPS
the candidate pool uses. `ssh -T git@github.com` → *"Hi Jsearle01! You've successfully authenticated"*;
`ls-remote` listed three heads; `git push --dry-run` of a throwaway branch returned `* [new branch]` exit 0 with
remote heads unchanged. Branch deleted. **Access exists.**

#### 3.2 — Phase 1: why the baseline mattered
Captured with the tree **unchanged at `23c0592`**. Two things it bought: the prod SHA `88eba89…` became the
reference that later proved byte-identity, and four passing tests became attributable. *Also discovered:* all 22
`.sh` runners hard-code WSL `/mnt/c/karateka-capture`; the `.bat` variants are the native-Windows path. Used the
`.bat` runners. A baseline attempted through the `.sh` runners would have failed for environmental reasons and
been misread as bit-rot.

#### 3.3 — Phase 2: flag 3, and why the earlier grep looked empty
P2.1's grep (and the dispatch's) searched for callers of the *undeclared* names and came back empty, which I
read as possible dead scaffolding. Searching **all file types across the whole tree** rather than `jsr` in
`src/` inverts it (§1). The likely reason for the earlier miss: `climb_controller.s` reaches three of them by
**`jmp`, not `jsr`**, and the fourth's heaviest use is in `tests/scripted/`. **Recommendation: declare all four
in `hal.inc`** — they are engine-called public functions and the contract under-declares itself. *No edit made.*

**Cross-project consequence, important:** because these are live in Karateka, **POP's P2.1 dormancy guard must
stay POP-LOCAL and must NOT be synced.** POP doesn't call them (compiled sprites); Karateka does. That is a
legitimate per-project *configuration* difference, exactly what P2.1's rule 3 contemplates — not a fork.

#### 3.4 — Flag 2: the relocation, and its payoff
`end boot` moved from `src/hal/coco3-dsk/mem.s` to a new `src/engine/entry.s`, listed last in `build.bat`. The
HAL no longer names an engine symbol. **Concrete payoff, measured:** POP's HAL build went 391 → **395 bytes** —
`mem.s` now assembles in POP, which it could not before (`Undefined symbol boot`). That is `HAL_mem_size_detect`
recovered.

#### 3.5 — Flag 1: what was achievable, and the blocker
`bit 5 = IEN`. `$4C` (IEN=0) is **correct** at `HAL_sys_init`'s early write; `$6C` (IEN=1) is **required** at
every write after `HAL_time_init` enables the VBL interrupt, because `$FF90` is write-only and no
read-modify-write is possible. One constant cannot serve both — so `hal.inc` was split into
`KCOCO3_INIT0_ACTIVATE` / `KCOCO3_INIT0_RUN` with that rationale inline.

The literals could **not** be replaced with the symbols. Tested, not assumed:
```
src/hal.inc(186) : ERROR : Only supported for object target (IMPORT)
        import  HAL_gfx_init            ; defined in src/hal/coco3-dsk/gfx.s
```
`hal.inc` is an **object-target** interface file in an **absolute-target** build, and is never included.
Both sites are therefore annotated with their constant name and the failure the value prevents. **The deeper
finding — that the entire shared interface file is unusable by the implementation it describes — is worth more
than the constant split, and is Jay's to act on.**

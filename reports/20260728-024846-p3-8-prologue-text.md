### 3 — Reasoning

#### 3.1 — PHASE 1a: Prolog1 and Prolog2 (AC1) — Jay's bet CONFIRMED

Authority: **source**, confirmed on the running oracle.

```
Prolog1                            Prolog2
 lda #pacProlog                     lda #pacSumup
 sta RAMRDaux                       sta RAMRDmain      <- from MAIN, not aux
 jsr DblExpand                      jsr DblExpand
 ldx #250 / lda #s_Prolog           jsr setdhires      <- AFTER the unpack
 jmp PlaySongI                      ldx #250 / lda #s_Sumup / jmp PlaySongI
```

`pacProlog` (`$7c`) and `pacSumup` (`$60`) are **`pac*`** blobs — the whole-image
family, the same as `pacSplash` — expanded by **`DblExpand`**, not `DeltaExpPop`.
**No text renderer exists or is needed: the story text is pre-baked pixels.**
Both are double hi-res 16-colour, same palette as the splash (verified: the
converter produced the identical 16 CoCo3 bytes for both).

**Page count: two, one picture each.** The attract order is
`TitleScreen → Prolog1 → PrincessScene → SetupDHires → Prolog2 → SilentTitle → Demo`;
there is no multi-page text loop.

**Measured on the running oracle:**

| | |
|---|---|
| title cleared | f1721 |
| `Prolog1` wipes in | f1721→~f1822 (~100 frames, **visible**) |
| `Prolog1` held | f1822→f2582 — **760 frames** |
| cutscene | f2688→f5600 (~49 s) |
| `Prolog2` appears **instantly** | f5752 |
| `Prolog2` held | f5753→f7317 — **1564 frames** |

**Why one wipes and one snaps** — and it is not incidental. `Prolog1` runs
`DblExpand` while its page is *displayed*, so the unpack is visible. `Prolog2`
unpacks **first** and calls `setdhires` **after**, so the mode switch reveals a
finished picture. POP flips for both: `Prolog2` matches exactly, `Prolog1` cuts
where the oracle wipes (§7.2).

**`ReloadStuff` does not apply.** `MASTER.S:862` is inside `PrincessScene`, not the
titles: the Apple's dhires pages (`$2000-$5FFF`) sit on top of the crunch store, so
the dhires screens eat their own source data. POP's framebuffers are banked physical
RAM outside the 64 KB map — nothing is overwritten, nothing needs reloading.

#### 3.2 — PHASE 1b: PrincessScene (AC3) — the STOP, confirmed

```
cutprincess1
 jsr LoadStage2            ; the GAME's level graphics (bgtab1-2, chtab4)
 lda #pacProom
 jsr SngExpand             ; SINGLE hi-res — a different video mode
 ... copy page 1 to page 2
PrincessScene: blackout / ReloadStuff / cutprincess1 / jmp xplaycut
```

`xplaycut` is the scripted cutscene player — the same one `TOPCTRL.S` uses for cuts
#1, #6 and #7. So this beat needs **a different decompressor** (`SngExpand`), **a
different video mode** (single hi-res 4-colour), **the game's character and
background tables**, and **the animation subsystem**. That is four capabilities, not
a table row. **Not built**; Jay's pre-authorized stop-at-the-finding taken.

In the port the two prologue screens therefore run back-to-back, where the oracle
has ~49 seconds of cutscene between them.

#### 3.3 — PHASE 1c: keypress during the prologue (AC4)

P3.7 established that `StartGame?` is polled only from `tpause` and `PlaySongI`.
Both prologue beats end in `PlaySongI` (X=250), so **the keypress check is live
throughout the prologue exactly as it is everywhere else in the intro** — the long
hold a player most wants to skip is skippable, by the same mechanism, with no
special case. Nothing further to scope beyond P3.7's finding: one poll inside the
sequencer's `hold_frames` covers every beat. **No input built.**

#### 3.4 — PHASE 2: beats 4 and 5 (AC2, AC6)

**Own-base support existed and had never been exercised.** The descriptor's
`BEAT_TRACK` field has been correct since P3.3 and no beat had ever set it.

**No-patch support did not exist.** Every beat ran the caption machinery
unconditionally, so a beat with `BEAT_PATCH = 0` would have called `patch_blit` on a
null pointer and walked memory from `$0000`. Added: a base-only beat skips straight
from the pre-hold to its own hold. **A capability the mechanism "supports" but has
never run is not yet a capability** — the first real use is where that shows.

**Base-only beats read their picture ONCE.** The second read exists solely so the
caption repair has a clean hidden copy; with no caption there is nothing to repair.
Reading twice cost **18 s** of stall per prologue screen; once costs 9 s.

Also: the loop's backward branch went out of 8-bit range and needed `lblo`.

**Disk layout** — the first assets outside the original span: `prolog1` tracks 9–15,
`prolog2` tracks 18–24, both clear of the track-17 directory, granules reserved.

**The two credits are not two screens.** The dispatch expected `PubCredit` and
`AuthorCredit` to be the same routine with different content. `MASTER.S:693-820` says
`AuthorCredit` has **no `unpacksplash` and no `copy1to2`** — it draws its byline straight
onto the picture `PubCredit` left behind, which `CleanScreen` had restored to both pages.
One screen, two captions. That is a better generalisation than the one requested, and it
is worth 26,880 bytes: modelling beat 2 as though it owned a picture would have been a
faithful-looking lie the machine cannot afford. `TitleScreen` is the same shape again.

**Both transitions are page flips, and so is the drawing.** Tracing the running oracle:
`f401` flip to the clean page, `f401-404` draw the caption on the now-hidden one, `f405`
flip back — the caption appears in one frame. The screen checksum does not move once
across those four frames of drawing. `f686` flip away — it vanishes in one frame — then
twelve frames of `copy2to1` on the page nobody is looking at. This is exactly what P2.6's
double-buffering was built for, so the sequencer spends flips rather than reinventing
them.

**Two infrastructure findings, both pre-existing, both now measured.** `LOADM` cannot
load any engine screen — a program at `$0200` overruns DECB's own buffers on its first
granule. P3.2's splash was never `LOADM`ed either; its harness poked the image in, which
is why nobody knew. And MAME had been writing the shared `.dsk` back, which corrupted it
mid-task and failed three unrelated tests at once.

### 3 — Reasoning

#### 3.1 — Phase 1: the Mechner beat is NOT the same structure (AC1)

Authority: **source** (`MASTER.S`), confirmed against the **trace**.

```
PubCredit      unpacksplash / setdhires / copy1to2 / tpause 44 /
               DeltaExpPop delPresents / PlaySongI 80 / CleanScreen
AuthorCredit                            tpause 42 /
               DeltaExpPop delByline    / PlaySongI 80 / CleanScreen
TitleScreen                             tpause 38 /
               DeltaExpPop delTitle     / PlaySongI 140 / CleanScreen
```

`CleanScreen` is `lda PAGE2on` → `copy2to1` → `lda PAGE2off`: flip to the clean page,
repair the dirty one behind it, flip back. The divergence is real and load-bearing — the
dispatch's §1 explicitly required reporting it rather than forcing the generalisation, and
the generalisation survives in a better form: **base-load is one optional step of a beat,
not part of its definition.** Three of the intro's beats are then the same mechanism.

Also worth recording: the "hold with the caption up" is not a `tpause`. It is
`PlaySongI`, which returns when the song ends and falls through to `tpause` only if music
is off. Timing is music-driven, which is why it was measured rather than computed.

#### 3.2 — Phase 1: what the flips actually do (AC1, AC5)

Authority: **trace** — a non-perturbing per-frame instrument on the running oracle,
sampling the rendered frame and `$C01C` (RDPAGE2, a non-toggling status read).

```
f306 base appears          f401 FLIP→p2   f405 FLIP→p1  caption 1 IN
f686 FLIP→p2  caption OUT  f698 FLIP→p1 (invisible; page repaired underneath)
f779 FLIP→p2               f782 FLIP→p1  caption 2 IN
f1065 FLIP→p2 caption OUT  f1076 FLIP→p1 (invisible)
f1149 FLIP→p2              f1183 FLIP→p1 title IN
```

The flip does the reveal **and** the hide, and the draw is hidden behind it in both
directions. `tpause` calibrates at ≈1.91 frames per unit against the three holds
(44→83, 42→80, 38→73 once `copy1to2`'s 12 frames are removed), but the beat table carries
the **measured visible transitions**, not that conversion.

#### 3.3 — Phase 2: the sequencer (AC2)

An 8-byte descriptor — `base`, `patch`, `pre` frames, `hold` frames — and one routine:

```
if base:  blit → back, swap, blit → back      (both pages hold the picture)
wait pre
patch  → back (hidden) ; swap                 caption APPEARS in one frame
wait hold
swap                                          caption VANISHES in one frame
undo   → back                                 repair, on the page nobody sees
```

**The invariant that makes a beat composable:** on entry and exit, both buffers hold the
clean base. That is what lets beat 2 carry no picture — it inherits a guaranteed state
rather than a hopeful one, exactly as `AuthorCredit` inherits `PubCredit`'s.

**One run list, two sources.** `patch_blit` walks the caption's geometry identically
whether it is filling from the patch's pixel bytes or from the base image, selected by one
flag. So the repair is guaranteed to cover exactly what the caption covered: no second
asset, no rectangle to keep in sync, nothing to get wrong independently. It replaces the
oracle's `copy2to1` — 16 KB and twelve frames — with ~750 bytes inside one frame.

The stream skip uses `abx` (unsigned), not `leax b,x`: accumulator-offset indexing is
**signed −128..+127**, the trap that sent the P2.7 probe walking backwards into itself.

#### 3.4 — Phase 2: why the captions are sparse (AC2)

Bounding rectangles do not fit, with the numbers rather than the assertion:

```
base image                          26,880 B
presents rectangle 108 x 45          2,430 B
byline   rectangle 112 x 25          1,400 B
                                  ----------  30,710 B   vs 30,208 available
```

But only 1,172 of the presents rectangle's 4,860 pixels differ from the base (24%), and
803 of the byline's 2,800 (29%) — the box is mostly unchanged picture. Sparse run lists:
**885 B and 687 B, 36% and 49% of the rectangles.** A patch that stores unchanged pixels
is not really a delta, so this is the faithful encoding as well as the affordable one.

#### 3.5 — Phase 3: the captures verify against the assets, not against "it looked right"

Five states dumped from the **displayed** buffer and compared byte-for-byte with an
offline replay built independently of the 6809 code:

- base == the converted splash, centred at bytes 10..149 (the +20 px contract)
- caption 1 == base + the presents patch — proves the run decoder **and** the column bias
- **caption 1's removal is exact** — byte-identical to the base, not "close"
- caption 2 == base + the byline patch **only** — the real test of the undo path, since
  the byline is drawn onto the page the first caption was drawn on. A failed repair shows
  up here as two captions at once.
- final == base

All five: **byte-identical**.

#### 3.6 — Reading the front buffer without disturbing the program

The CPU can only see the BACK buffer; the displayed one is reachable only through
write-only VOFFSET. The harness therefore maps the front buffer into the window for one
read and puts the back one straight back — safe because the MMU affects **CPU addressing
only** (the display does not care), the program is parked in a `HAL_time_vbl_wait` loop
touching nothing in `$8000-$FFFF` for hundreds of frames, and the restore value is
computed from `HAL_gfx_cur_back` rather than read back from write-only registers.

The contrast is deliberate and was learned the hard way this task — see §6.

#### 3.7 — The memory wall (reported, not solved)

Kernel `$7000` → `$7900`, the highest start that clears the trace buffer at `$7800` and
leaves usable stack below `$7F00`. Measured placement from `build/obj/introseq.map`:

```
prog  $0200..$72AD   28,846 B      (assets 28,468 + code 378)
code  $7900..$7B79      634 B      gap $72AE..$77FF = 1,362 B free
```

**94% full.** The title patch does not fit at any kernel address. `$7B79` is also near the
real ceiling: DECB's stack sits at about `$7F2B`. Screen assets belong in high physical
RAM mapped through the MMU, and that should be taken **before** the next screen.

### 6 — Reactive deviations (§22.5)

1. **The image is poked in, not `LOADM`ed.** `LOADM` cannot load any engine screen —
   idioms §23. Not a choice made for convenience: it is the only path that works today,
   and it is the same path P3.2 used. Reported rather than worked around silently.
2. **Three existing runners now mount a scratch disk copy.** MAME had been writing
   `build/probe.dsk` back; mid-task it went to `Corrupt image` and probe/mode/anim all
   failed at once with nothing wrong in any of them. Idioms §24. Necessary to run the
   suite at all.
3. **Kernel moved `$7000` → `$7900`** to fit the assets. Link-script only.
4. **My first oracle trace corrupted the run.** To checksum both banks it wrote
   `$C002`/`$C003` every frame — soft switches the *game* owns. The capture at frame 900
   came back a different image with the displayed page's banks 848/8192 apart instead of
   ~7,450. Rewritten to write nothing and sample the rendered frame instead; clean on the
   first run. Recorded in the script's header so it is not re-derived.
5. **A second instrument did the same thing.** The `LOADM` probe pre-cleared `$0200-$1FFF`
   for a clean canvas, wiping DECB's `$0600+` workspace, and reported that *every* case
   failed — including ones already known to work. Caught only by that contradiction.
6. **Two beat-finder passes were wasted on `-video none`**, where `scr:pixels()` returns a
   buffer that never updates. Read as "the screen never changed".

### 7 — Uncertainty flags

1. **No engine screen has ever been loaded from disk.** Everything graded so far, P3.2 and
   P3.3, ran from a poked image. The disk path is unexercised for anything past one
   granule, and Jay's gates say nothing about it.
2. **The timing runs 1–2 frames long per beat** (+100 vs +99, 282 vs 281, +97 vs +96, 285
   vs 283). The swap's own VBL wait is not subtracted from the hold. Deliberate and
   sub-perceptual; correctable by subtracting one frame per swap if it ever matters.
3. **The pipeline still needs the oracle.** Display-faithful conversion converts a captured
   rendered frame, so no asset can be built from the disk image alone (carried from P3.2).
4. **`$FF2A`-style FDC interaction under double speed is still PROVISIONAL** (§2G) and
   untested by POP — it will be the boot arc's problem, not this one.
5. **Why MAME wrote the `.dsk`** is not established — only that it did, that it corrupts,
   and that mounting a copy prevents it.

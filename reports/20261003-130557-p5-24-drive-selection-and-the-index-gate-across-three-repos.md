### 3 — Reasoning

#### 3A — §2's design question: can the siblings' bytes stay identical? Yes, by a guard

*Authority: the source, then measurement (§0).*

**Everything new is under `ifdef HAL_DISK_DRIVE_SELECT`.** The six DSKREG writes become
`ifdef … lda #DSK_POS_ND / ora dr_drive … else lda #DSK_POS … endc`, with **today's instruction
verbatim in the `else` arm**, so a build without the flag assembles exactly what it did. **No shipped
build in any repo defines the flag**: POP's `build.bat` doesn't, and neither sibling has it. Only
`run_side_check.sh` assembles a separate `build/p524/hal_build_ds.o` with it. §2M.3 governs this: *"a
guard is the mechanism that lets identical source assemble differently"*. The guarded code is identical
in all three trees, and §2M.4 is met by the new exports arriving in all three at once.

**Why that and not "new entry points, default drive 0" unguarded:** unguarded, the new routines would
assemble into every sibling's binary and shift what follows. Karateka's bootloader alone embeds the
file. **That would have moved sibling bytes**, which §2 makes Jay's decision. The guard avoids needing
one.

**`hal.inc` is not touched.** Clients import the disk entry points directly, as `tile_probe.s` already
does, so the change is confined to one shared file.

#### 3B — AC4/AC5/AC10: the presence gate, and why the old bound did not protect

`dr_wait_notbusy` is bounded ($8000 polls), but **on timeout it returns exactly as if Busy had
cleared.** On an absent drive, `disk_read` would time the Restore out silently, issue the read, arm
HALT, and hang. **The existing bound bounds the wait, not the consequence.**

`disk_present` (HALT never armed):
1. select + motor (HALT off), `dr_spinup` (0.6 s if cold), Force Interrupt for a clean Type I status;
2. **Restore with its own bound (~0.74 s) that REPORTS a timeout.** On timeout it Forces Interrupt to
   free the FDC and returns C set with 0 edges. This is the "no drive" case, **covered by the bound** (AC4);
3. index-pulse edges over ~0.63 s (Type I b1); **C clear only on ≥ 2 edges**.

**AC10 — decision times, measured per step (MAME):**

| case | warm | cold (spin-up owed) |
|---|---|---|
| match | 0.80 s | 1.22 s |
| empty drive | 0.65 s | 1.08 s |
| no drive | 0.75 s | 1.19 s |
| wrong signature | 0.78–0.80 s | 1.22 s |
| **unformatted disk (worst)** | **1.60 s** | **2.02 s** |

**Worst case ~2.0 s** (a turning disk with no sectors: the read runs ~5 revolutions to RNF). A
first-time check on a cold motor costs ~1.1–1.2 s whatever the answer.

#### 3C — AC6/AC7/AC9: the signature, and the condition Jay put on it

**A design finding first: side A cannot carry its signature where side B does.** P5.22 put `POPB` at
track 0 sector 1. **On side A that sector is `LOADER.BIN`'s first sector**, because DECB allocates
granule 0 to the first file, and the probe read exactly that there (`00 01 E6 0E 00 1A 50 10 …`, a DECB
preamble). So each side's signature sits where **its own format** leaves a sector unused:

| side | location | why |
|---|---|---|
| **B** (raw) | **track 0, sector 1**, head of its directory sector | P5.22's side directory |
| **A** (DECB) | **track 17, sector 18** | DECB writes only sectors 2 (FAT) and 3–11 (directory); a fresh image is `$FF` in 12–18 |

**Same routine, location as a parameter**, so it remains one mechanism. **Content: 16 ASCII bytes
`POP COCO3 SIDE A`/`B` + format version `$01`**, 17 bytes compared. P5.22's 4-byte `POPB` was lengthened
because the condition is uniqueness, and length costs nothing.

**AC6 — uniqueness, against what a player might really have in drive 1** (each read at side B's
location, and at side A's in step 4):

| disk in drive 1 | at side B's location (T0 S1) | verdict |
|---|---|---|
| **truly unformatted** (DMK, no sector IDs) | **read fails: RNF, status `$10`**, no hang | not side B |
| freshly **DECB-formatted** | `FF FF FF …` | wrong signature |
| **random-data** DECB disk (six seeded random files) | `14 CC 52 4D E8 19 …` | wrong signature |
| **POP side A** | `00 01 E6 0E 00 1A …` (LOADER.BIN) — **and MATCH at side A's location** | identified as side A |
| **karateka boot** disk | `00 01 89 80 00 1A …` | wrong signature |
| **karateka game** disk (raw) | `3B 12 12 3B 12 12 …` | wrong signature |
| **POP's shipped `probe.dmk`** | `00 00 95 02 00 7E …` | wrong signature |
| **POP side B** | `POP COCO3 SIDE B\x01` | **MATCH** |

**The only matches were the right side at its own location.** Side A's location read `FF…` on every
other disk.

**AC7 — validity:** side B on drive 1 matched with identical bytes **cold, warm, on re-read, and after a
cold Restore**. On drive 0 (flipped) it matched. Side A on drive 0 matched warm and cold in all 11
configurations. **Every repeated read returned the same 17 bytes.**

**AC8 — the condition is met on what was tested, so no fallback arises.** The limit, stated rather than
softened: this is MAME's WD1773 and seven disk images, and §7 carries the real-hardware caveat.

**AC9 — `POPA`:** side A now carries `POP COCO3 SIDE A` at T17 S18 (`make_side_dmk.py --sig-…`). The
**flip-back check is the same `side_check`** with side A's descriptor (steps 6–7), the oracle's own
`GOATTRACT`/`flipdisk` pattern [`TOPCTRL.S:1241-1264`].

#### 3D — §5: the policy, one path in two places

`side_check(drive, descriptor)` [`side_check_probe.s`] = `disk_select_drive` → **`disk_present`** →
**only then** `disk_read` → compare. The four cases map to its reasons: **0 MATCH** (use that drive),
**1 no disk turning** (empty or absent → flip), **2 wrong signature** (flip), **3 read failed** (an
unformatted or unreadable disk → flip), **4 bad drive number**. **The flip prompt re-runs the same call
on drive 0 until reason 0**, so a wrong flip is caught by the mechanism that caught the wrong disk.

**AC11 — where it should run, named, not wired:** at **the moment side B is first needed**, the first
level after the intro and cutscene (P5.22 §3I). It costs ≤ ~1.2 s cold in the common cases and ≤ 2.0 s
worst, so it sits behind the same transition as the first side-B load. The order: **drive 1 first; if it
does not match, prompt and check drive 0.** It is **not** wired into the intro here.

### 7 — Uncertainty flags

1. **★ MAME, not hardware.** The empty / absent / unformatted behaviours are MAME's WD1773 model. On real
   hardware, a missing drive might not hang Busy, and an empty drive's index line might float. **The gate
   is written so neither changes the answer** (no index edges → "no disk"; a Restore timeout → "no disk"),
   but the decision times will differ.
2. **Seven wrong disks is a sample.** The 17-byte compare makes an accidental match vanishingly unlikely,
   but a deliberately copied signature would of course match.
3. **The index window assumes ≥ 2 edges in ~0.63 s** (300 rpm gives ~6). A drive running far slow would
   need a longer window.
4. **`disk_select_drive` clears `dr_motor_on` on a drive change**, which is conservative (0.6 s) because the
   CoCo motor line is shared. Measured as part of the cold times.

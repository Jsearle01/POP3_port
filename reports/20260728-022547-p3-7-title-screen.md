### 3 — Reasoning

#### 3.1 — PHASE 1a: the title's render spec (AC1) — REFUTES the dispatch

Authority: **source**, corroborated by a second call site.

```
TitleScreen
 lda #38 / jsr tpause
* Unpack title onto page 1          <- the comment the dispatch's grep found
 lda #delTitle
 jsr DeltaExpPop                    <- the CALL: a delta, not an unpack
 ldx #140 / lda #s_Title / jsr PlaySongI
 jmp CleanScreen
```

That is **byte-for-byte `AuthorCredit`'s shape**. The identifier families are the
structural evidence:

```
pac*  whole images   pacSplash $40  pacProlog $7c  pacSumup $60  pacProom $84
del*  patches        delPresents $70  delByline $72  delTitle $74
```

`unpacksplash` is `lda #pacSplash / sta RAMRDaux / jmp DblExpand` — a different
routine and a different family. And `SilentTitle` is unarguable:

```
SilentTitle
 jsr unpacksplash        <- loads the base picture
 jsr copy1to2
 lda #20 / jsr tpause
 lda #delTitle / jsr DeltaExpPop     <- then applies the title ON TOP
```

**Spec:** own image **no** — a caption over the Brøderbund splash; mode unchanged
(same stage-1 double-hires 16-colour); content "Prince of Persia" title art; timing
`tpause 38` then a 140-unit song hold; assets in the same stage-1 aux batch (P3.4).

**`ReloadStuff` does not apply.** `MASTER.S:862` sits inside `PrincessScene`, not
`TitleScreen`: it reloads aux `$2000-$5FFF` because the dhires *pages* overlap the
crunch store on the Apple. POP's framebuffers are in banked physical RAM outside the
64 KB map, so nothing is overwritten and nothing needs reloading.

#### 3.2 — PHASE 1b: when keypress goes live (AC2) — CONFIRMS Jay

Authority: **source**, then **the running oracle**.

`StartGame?` is *defined* at `MASTER.S:996`, after `TitleScreen` in the file — which
is what made it look like a late-attract check. It is **called** from exactly two
places, and both are hold primitives:

```
MASTER.S:1400   :loop jsr StartGame?     inside PlaySongI
MASTER.S:1417   :loop2 jsr StartGame?    inside tpause  (~512 polls per unit)
```

Every beat holds with one or both, so the check runs throughout — **starting with
`PubCredit`'s first `tpause 44`, while the splash is up and before any caption.**

reading mistook where the routine is defined for where it runs.

**Scope for future input work (built: none).** Polling belongs in the sequencer's
`hold_frames`, not per-beat — one check there covers every beat, which is exactly
where the oracle put it.

#### 3.3 — PHASE 2: beat 3 (AC3, AC4)

**The sequencer generalised.** `BEAT_COUNT` 2→3 plus a table row was the only
structural change; P3.5's terminate is `incb / cmpb #BEAT_COUNT / blo`, so it keyed
on the constant as intended. Two things still needed fixing, both mine:

- **"done" was a hardcoded `4`**, which now collides with beat 3's status (beat+2).
  It derives from `BEAT_COUNT` now.
- **The runtime map had to move above the engine.** The bundle went 1→2 tracks
  (9,216 B) when the title joined it; at `$0A00` that runs through `$2000` and over
  the engine. Bundle `$3000-$52FF`, save buffer `$5400`, `DR_VARBASE` `$6A00`.
- **`SAVE_MAX` 768→6144.** `patch_blit` saves the bytes it is about to overwrite, so
  the buffer must hold the **largest** patch's pixel bytes — the title's 5,361, not
  the captions' 747.

**One timing subtlety.** The title first landed at **+125** against the oracle's
+118, where every other beat drifts by 1. Its patch is 5,909 B against 885, so the
draw itself costs ~6 frames — the captions draw in well under a frame, so their
`BEAT_PRE` *is* the measured interval, while the title's has to pay the draw out of
the hold: `118 - 6 = 112`. Re-measured at **+119**, the same +1 as the others.
